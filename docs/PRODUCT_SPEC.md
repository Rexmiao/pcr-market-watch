## 1. 产品目标与当前边界

用户可以维护自己的美股观察名单与分组，查看个股/ETF 的 OCC 成交量 PCR，以及 Cboe INDEX、TOTAL、ETP、EQUITY 四类市场汇总 PCR，并清楚分辨数据日期、检查时间、覆盖范围和缺失值。

| 能力 | 当前源码状态 | 边界 |
| --- | --- | --- |
| 自选与分组数据库 | 已实现 API、前端模型和数据库迁移 | 云端用 D1；本机预览用独立 SQLite，两者不自动互相复制 |
| 初始默认标的与新增标的统一管理 | 已实现 | 默认名单只用于首次初始化；没有不能删除的核心标的 |
| OCC 个股/ETF 成交量 PCR | 已实现 | 完整日来源，不提供盘中实时 PCR；新增标的有独立覆盖范围 |
| 可编辑的市场 PCR 名单与历史 | 已实现独立配置 API、模型与编辑入口 | 首次推荐四类 Cboe 及 SPY、QQQ、DIA 共七项；推荐项均可删，也可新增支持的 Cboe 类别和合法 OCC 个股／ETF；与原个人名单独立 |

| moomoo 本机行情后端 | 已实现只读适配接口 | 依赖本机 CLI、行情服务及实际权限；不代表已有完整行情终端界面 |

| 交易、持仓账户操作 | 不在本产品范围内 | 不查询账户/持仓，不下单、改单、撤单或解锁交易 |

## 2. 用户故事

### US-01：维护自己的名单与分组（P1）

用户希望默认标的和后来加入的标的遵守相同规则，可以添加、删除、分类和恢复；网页支持创建自建分组、删除默认或自建分组。当前网页没有分组重命名入口，API 整体保存 groups 时可以修改名称。

独立验收：建立两个用户的名单；删除第一个用户的全部默认标的，新增 SNDK，创建中文分组，移动标的，删除分组，再重新打开页面。结果应来自数据库，第二个用户的名单不受影响。

### US-02：看懂当前读数与历史窗口（P1）

用户选择一个日期，查看单日、20 日和 60 日 PCR，以及来源与覆盖日期。没有该日完整报告时，页面要展示缺失或等待来源，而不是拿前一日数字冒充当天。

独立验收：用相同原始 Put/Call 数量分别复算三个周期；选择未发布日、历史日和一段有缺口的 Cboe 记录，检查空态、历史截止日及 OI 显示规则。

### US-03：多窗口保存不互相覆盖（P1）

用户在两个浏览器窗口编辑同一份名单时，较晚提交的旧版本不能悄悄覆盖另一窗口的新版本。

独立验收：两个窗口从相同 revision 保存不同名单；只有一个保存成功，另一个收到冲突，并显示服务器当前的名单和分组。

### US-04：在本机读取 moomoo 行情（P2）

用户在本机预览中读取报价、日 K、期权到期日及指定到期范围的期权链。连接或权限失败时显示实际失败状态，不能暗示已经取得实时行情。

独立验收：使用可控的 CLI 测试响应验证允许的查询、时间戳、超时和错误；确认交易或任意命令无法从网页调用。

### US-05：自由编辑市场 PCR 参考（P1）

用户希望上方市场 PCR 也能添加和删除。首次推荐 INDEX、TOTAL、ETP、EQUITY 四类 Cboe 与 SPY、QQQ、DIA 三只 OCC ETF，不意味着这些入口永久固定。合法 OCC 个股或 ETF 可以加入同一选择器；各项保留自己的来源与覆盖日期。

独立验收：删除全部七个推荐项并重开，名单仍为空；添加 SNDK 及一个与 Cboe 类别同文字的 OCC ticker，来源标识和曲线互不混用。更改市场名单不改变原个人名单或分组，反向操作也不联动。

### US-06：选择介绍页及文档语言（P1）

访客可以在 GitHub Pages 介绍页切换中文与英文，并进入对应语言的 README 和产品 Spec；回访时保留自己的语言偏好，英文演示图片与 GIF 保持原样。

GitHub 仓库默认展示英文 `README.md`；完整中文版保存为 `README.zh-CN.md`，`README.en.md` 保留为完整英文兼容副本。此仓库默认语言不改变介绍页默认中文或应用内已有语言偏好。

独立验收：用中英文直达链接打开 `#preview`，切换语言、打开演示弹窗和文档链接，再次访问；检查语言、元信息、文档目标及手机布局。

## 3. 名单与分组需求

| 编号 | 要求 |
| --- | --- |
| WL-001 | 一份用户配置同时保存 `items` 和 `groups`，整体替换并共享一个 revision。 |
| WL-002 | `items` 最多 30 个去重后的 ticker，保持用户提供的顺序；重复 ticker 保留首项。 |
| WL-003 | ticker 去除首尾空白、转为大写，仅接受 ASCII 字母开头及字母、数字、点号，总长 1–10。 |
| WL-004 | 每项为 `{symbol, category}`；category 为存在于 groups 的 id，或 `null` 表示未分类。 |
| WL-005 | `groups` 最多 30 个，每项为 `{id, name}`。id 接受 `semi`、`etf`、`other` 或 `custom_` 加 1–64 位字母、数字、下划线、连字符。 |
| WL-006 | 分组名去除首尾空白后为 1–40 个字符，不包含控制字符；id 不重复，名称按去空白及大小写不敏感规则不重复。 |
| WL-007 | 网页支持创建自建分组、删除所有默认或自建分组；API 整体保存 groups 时可修改组名，当前网页没有重命名入口。`全部` 和 `未分类` 是派生视图，不是数据库分组。 |
| WL-008 | 删除分组时，同一次保存将其原有标的的 category 改为 null，保留这些股票；提交孤立 category 时拒绝保存。 |
| WL-009 | `items=[]`、`groups=[]` 都是有效的已保存状态。重新加载或新增标的时，不自动恢复已删除的默认项/默认组。 |
| WL-010 | 无记录时 GET 返回未初始化状态；只由前端首次迁移默认名单、旧浏览器自选及默认分组，并以 revision 0 提交一次。 |
| WL-011 | 移除自选只改变个人配置，不等于删除公共行情缓存。之后可以重新添加相同 ticker。 |
| WL-012 | 搜索建议是少量已整理公司名/中文名目录；也支持直接输入合法 ticker，不宣称覆盖全市场公司名称检索。 |
| WL-013 | 搜索框使用通用“输入股票或 ETF 代码”提示，不固定展示 SNDK。鼠标或方向键改变高亮；Enter 直接添加高亮候选，没有候选时使用当前输入代码。不能使用上次搜索的旧候选。 |
| WL-014 | 输入法组合中的 Enter 只用于确认输入；长按、重复 Enter、已关注代码与保存期间不能产生重复记录。无有效行情记录时不添加。 |

## 4. 配置数据与 API 契约

### 用户配置

数据库表为 `user_watchlists`，字段为 `owner_id`、`items_json`、`groups_json`、`revision`、`updated_at`。数据库迁移只定义结构，不写用户名单或默认分组；请求处理过程中不创建或修改表结构。

云端从平台提供的 `oai-authenticated-user-id` 决定 owner。请求体、查询参数或服务访问凭证不能选择个人数据的 owner。没有用户身份返回 401。本机预览由服务端注入 `local_user`，对应本机单用户配置，不代表实现了多用户登录。

### 读写

| 请求 | 行为 |
| --- | --- |
| `GET /api/watchlist-settings` | 返回 `{items, groups, revision, updatedAt, storage, initialized}`。没有记录时 items/groups 为 null、revision 为 0、initialized 为 false；不写数据库。 |
| `PUT /api/watchlist-settings` | 仅接受 `application/json` 的 `{items, groups, revision}`；完整请求体最多 8192 字节，仅接受同源请求。 |
| 首次 PUT | revision 必须为 0，通过原子插入建立 revision 1；若其他窗口已经初始化则返回 409。 |
| 后续 PUT | 只有数据库 revision 与请求一致时，才原子替换 items/groups 并将 revision 加 1。 |
| 冲突 | 返回 409 和服务器当前的完整配置；前端采用当前值，不能用旧编辑内容自动覆盖。 |
| 失败 | 输入错误、身份缺失、数据库不可用分别明确返回错误。未确认的保存不当作成功，不静默切换成浏览器名单。 |

示例请求：

```json
{
  "items": [
    {"symbol": "SPY", "category": null},
    {"symbol": "SNDK", "category": "custom_chips"}
  ],
  "groups": [{"id": "custom_chips", "name": "芯片观察"}],
  "revision": 3
}
```

`storage` 为 cloud 或 local，表示当前实际使用的数据库环境；不表示本地 SQLite 已同步到 D1。浏览器可保留语言等设备偏好，个人名单以数据库响应为准。

### 独立的市场 PCR 配置

市场 PCR 保存到独立表 `user_market_pcr`；原 `user_watchlists` 的个人名单和分组不因此迁移或互相联动。来源缓存可共用，但删除配置项不删除公共缓存，也不能因缓存仍存在就把该项重新加回名单。

| 请求或规则 | 契约 |
| --- | --- |
| `GET /api/market-pcr-settings` | 读取当前身份的市场名单。未初始化返回 items=null、revision=0、initialized=false；GET 不写记录。 |
| `PUT /api/market-pcr-settings` | 仅接受同源 JSON 请求，完整体最多 8192 字节；整体保存 `{items, revision}`，使用独立 revision 进行原子首次插入或比较后更新；冲突返回服务器当前名单，不自动覆盖。 |
| 市场项 | Cboe 为 `{type:"cboe", key:"index"|"total"|"etp"|"equity"}`；OCC 为 `{type:"symbol", symbol:"SNDK"}`。每项只接受相应的两个字段。 |
| 数量与去重 | 最多 40 个去重项并保持顺序；Cboe 类别与 OCC 大写 ticker 使用不同来源命名空间，不跨来源合并。 |
| 首次推荐与清空 | 仅未初始化时可以一次保存推荐七项；已保存 `items=[]` 是有效配置，重开、源失败或读取失败均不得恢复推荐项。 |
| 身份与隔离 | 延续平台可信身份、同源请求和数据库错误规则；市场名单与个人名单的内容、revision 和初始化状态分别处理。 |

例如 `{type:"cboe",key:"index"}` 与 `{type:"symbol",symbol:"INDEX"}` 是两个不同条目。前者读取 Cboe 指数分类，后者只有取得该 ticker 的 OCC 记录后才能展示其个股／ETF PCR；不能因名称相同而冒用另一来源的数据或标签。

## 5. PCR 与时间定义

### 计算口径

设某窗口内已验证的 Put 数量为 P、Call 数量为 C：

- 单日成交量 PCR：当日 P / C。
- 20 日成交量 PCR：对应窗口内 sum(P) / sum(C)。
- 60 日成交量 PCR：对应窗口内 sum(P) / sum(C)。

20/60 日值不能用每日 PCR 的算术平均替代；Call 分母为零、历史不足或必要数据不可用时返回 null，页面显示缺失，不显示无穷大或虚构数值。

| 来源 | 范围与当前实现 |
| --- | --- |
| [OCC Volume Query](https://marketdata.theocc.com/volume-query) | 按单个 underlying 汇总来源合约侧数，单位为 contract sides。当前 20/60 窗口按已取得的活动记录行计算，coverage 会说明范围；缺失日期不补零。这与经过完整交易日校验的窗口不是同一个保证。 |
| [Cboe Daily Market Statistics](https://www.cboe.com/markets/us/options/market-statistics/daily) | 分开保留 INDEX、TOTAL、EXCHANGE TRADED PRODUCTS、EQUITY。直接来源单日使用官方发布的两位小数 PCR；历史重建 EQUITY 另标派生口径，详见 CBOE_SOURCE_SCOPE.md。20/60 使用有效 Put/Call 总量重新合计，窗口必须包含连续 20/60 个预期交易日及成交量，任何缺口使该窗口为 null。 |

Cboe INDEX 不是 SPY/QQQ/DIA 的 ETF PCR。各类别不可互换，个人分组也不改变来源口径。PCR 不表示做空人数、看空资金占比、股票空头持仓比例或未来涨跌概率。

新增 ticker 的历史与刷新状态独立保存；没有数据不能导致其他标的退回更早日期。选择图表显示长度不应改变同一日期的 20/60 窗口数值。

### 历史水平与往年同期

市场历史区提供“不比较”“历史分位”“往年同期”三个模式，属于查看偏好，不修改名单。标准模式保留单日、20 日、60 日三条成交量 PCR；年度对照一次只比较其中一个指标，避免六条曲线同时重叠。

| 编号 | 可核查规则 |
| --- | --- |
| HC-001 | 先按所选截止日找到实际记录日。单日只与单日比，20 日只与20 日比，60 日只与60 日比；不跨标的、类别或来源合并样本。 |
| HC-002 | 各指标独立选实际记录日之前最近最多252个有限有效值；排除当前日及未来值。图表显示长度不改变分位计算样本。为此Cboe读取已保存完整历史，再在前端裁剪显示区间。 |
| HC-003 | 分位采用中位秩 `(低于当前值数量 + 0.5 × 等于当前值数量) / n`。同时展示历史中位数及实际样本数 `n / 252`；不足252明确标注，n=0或当前值缺失则分位为空。 |
| HC-004 | 年度曲线以所选日所属年份，与上年同月同日精确对齐，保留原始数据日期用于悬浮说明；非交易日、缺记录和无对应的2月29日留空，不补零、不插值。 |
| HC-005 | 年度摘要目标日为实际记录日减一年，2月29日目标调整为2月28日。摘要允许使用目标日前7天内最近一条记录，必须同时标目标日、实际比较日；无记录留空。此回退不用于年度曲线填充。 |
| HC-006 | 同期差值为当前PCR减去年PCR的倍数差，不称为百分比收益。展示可比较日期数及可用范围；样本不足不暗示完整多年历史。 |

历史分位反映相对活跃程度；99.6%不表示99.6%资金看空，也不表示预测成功率。年份对照只描述历史差异，不证明季节性因果或交易优势。

### 日期与检查时间

| 字段或概念 | 含义 |
| --- | --- |
| requestedDate / requestedEnd | 用户想查看的日期，不保证来源已发布。 |
| asof / actualEnd / 活动日期 | 已核实数据所描述的日期；历史图只延伸到实际取得的最后日期。 |
| checkedAt / 抓取时间 | 系统检查或取得数据的时间，不是交易日，也不证明数据刚刚发生。 |
| source / sourceUrl | 原始发布机构与可核查来源地址。 |
| completedSession | 按纽约时间及交易日历认定的最近已完成交易日。 |
| pending_source | 已收盘但来源尚未返回相应完整日数据；不能承诺固定发布时间。 |
| market_open | 交易时段内，完整日 PCR 仍截至已发布日，不能称为今天盘中读数。 |

刷新失败时保留最后一次已核实数据并标明失败；不把检查时间更新误写成来源活动日期更新。Cboe history GET 只读取 seed/cache/memory，手动刷新每批最多检查 15 个缺失日期；剩余缺口需明确显示，不能一个点击循环抓完整历史。

### OI 快照

OI PCR 为未平仓 Put 数量 / 未平仓 Call 数量，与成交量 PCR 分开显示。已有 OI 属于单次缓存，quoteTimestamp、fetchedAt 与实际结算日是不同概念。实际 OI 结算日未披露时必须保持未知，不从报价时间推算。

成交量更新按钮不更新 OI。没有可信 OI 来源的新 ticker 返回 null；选择历史日期时，不能将最新 OI 快照当作当天历史 OI。股票 short interest 与期货持仓也不由此快照推导。

颜色语义按图表分别标注：趋势图浅蓝为单日成交量PCR、深蓝为20日、橘色为60日；对比柱状图蓝色为选定窗口成交量PCR，灰色为独立OI快照。新增SNDK等缺OI时灰柱缺失表示“未取得”，不表示持仓为零。两类PCR不能相减当作新增空头。

## 6. moomoo 本机后端与保密边界

官方 moomoo 文档将“读取自选分组”和“读取某组证券”分成两个接口，本文借鉴这种组与成员分开的组织方式；当前本产品的数据库自选独立维护，尚未接入 moomoo 自选名单同步。[读取分组](https://openapi.moomoo.com/moomoo-api-doc/en/quote/get-user-security-group.html)、[读取组内证券](https://openapi.moomoo.com/moomoo-api-doc/en/quote/get-user-security.html)。

当前本机链路为：浏览器 → 绑定 loopback 的 Node 预览后端 → 固定 CLI 可执行文件 → loopback moomoo 行情服务。云端 Worker 不包含这条本机进程调用链。

| 编号 | 要求与当前限制 |
| --- | --- |
| MM-001 | 浏览器只能调用固定 GET 行情接口：status、quotes、kline、expirations、option-chain。 |
| MM-002 | CLI allowlist 仅有 subscribe、get-basic-qot、get-kline、get-option-expiration-date、get-option-chain；行情订阅只用于取得数据，不提供任意 CLI 命令入口。 |
| MM-003 | 子进程使用参数数组及 shell:false；用户不能指定命令、任意标志、外部 host 或凭证。行情服务 host 仅接受 loopback。 |
| MM-004 | 一次最多 20 个美股代码；日 K 最多 1000 根；期权链最多一个日历月的到期范围。该范围的链不等于全到期日 PCR 或全市场 OI。 |
| MM-005 | 供应商行情时间戳与 checkedAt 分别保留。连通、订阅成功或返回数据，不自动证明实时行情权限已核实。 |
| MM-006 | AppKey 由本机后端环境变量或 Windows DPAPI 加密存储读取；环境变量可覆盖本机存储。配置脚本的输入不回显，DPAPI 文件位于项目与 Dropbox 之外、绑定当前 Windows 用户，换电脑或用户需重新配置。凭证不放进浏览器、URL、源码、数据库配置文档、Git 提交或发布归档；错误信息需脱敏。 |
| MM-007 | 本机数据库、账户资料、持仓截图、私人行情响应和凭证文件不作为公开源码或公共种子数据。测试使用虚构身份与临时数据库。 |
| MM-008 | 不开放账户、持仓、订单、交易解锁、下单、改单、撤单等命令。 |

云端的 localhost 指向云端运行环境，不能据此访问用户电脑。个人电脑关闭、本机预览停止或 moomoo 服务停止时，这条本机行情链路不可用。云端公共 PCR 与云端 D1 名单依赖云端服务，与个人电脑是否开机分开判断。

受控云桥、用户主动上传脱敏快照或其他远程同步方案属于待选后续，当前未选型、未实现，也不纳入本轮已完成功能。

## 7. 验收场景与成功标准

本轮页面采用“行情参考条 → 市场 PCR → 自选标的 PCR → 来源说明”的顺序。
PCR 是主要任务，行情及解读只提供辅助事实，不自动生成开仓、止损或涨跌概率结论。

- 市场选择器首次推荐四类 Cboe 汇总及 SPY、QQQ、DIA 三个 OCC ETF 参考，所有推荐项均可删，并可加入支持的 Cboe 类别或合法 OCC 个股／ETF；同一历史图沿用各自来源、日期和缺失值，不能把 ETF PCR 称为直接指数期权 PCR。
- 市场名单与原个人名单独立保存。个人名单删除 SPY、QQQ、DIA 不自动移除市场名单中的同名条目；市场名单中的条目仍可由用户自行删除，修改任意一方也不自动增补另一方。
- 行情条显示标普 500、纳斯达克综合、道琼斯、WTI 原油期货、COMEX 黄金期货。纳斯达克综合行情与 QQQ 所参考的纳指 100 是不同指数，标签明确区分。
- 行情条可随页面滚动悬浮，也可取消；手机在条内横向浏览，不能造成整页横向溢出。
- 行情以 Yahoo Finance 源前收价计算涨跌，保留各自报价时间、合约名及检查时间；可能延迟，失败不把保留价标成新报价。
- 搜索结果支持鼠标与方向键高亮；Enter直接添加当前高亮候选或输入代码；点击“添加标的”仍可使用。Escape 和 Tab 可离开建议列表，输入法确认与重复按键不产生意外添加。
- 图表目录从数据库读取当前名单，有更新按钮，不写死七个标的，也不刷新固定归档内容。
- 市场解读以两段已加载事实和一张名单表呈现，可更新；本机可用 moomoo 行情时，常规、盘后、夜盘价格分别标注，未知时间不推断。没有接入聊天模型或新闻流。
- 原 2026-11-23 市场解读作为固定日期归档保留，不再用作当前市场首页。

| 场景 | 可核查结果 |
| --- | --- |
| AC-01 首次访问 | GET 未创建用户记录；前端仅一次首次 PUT 迁移默认项与旧自选，得到 revision 1。 |

| AC-04 空分组持久 | groups=[] 重开仍为 []；新增标的默认未分类，不复活 semi/etf/other。 |

| AC-09 Cboe 缺口 | 删去一个预期交易日后，所有包含该日的 20/60 窗口留空；移出窗口后恢复计算，不补零或插值。 |

| AC-12 本机持久 | 关闭并重开本机预览后，SQLite 名单/分组保留；本机配置不会冒充已写入云端。 |
| AC-13 moomoo 限制 | 测试覆盖 allowlist、参数校验、loopback、超时、权限失败及凭证脱敏；无交易命令路径。 |
| AC-14 云端说明 | 页面或文档不宣称云端已经连接个人电脑，不将尚未实现的云桥写成已完成。 |
| AC-15 市场名单清空 | 首次推荐项全部可删；保存 items=[] 后，重开、切换日期、源失败或重新读取均不恢复默认七项。 |
| AC-16 市场来源身份 | 同时存在 Cboe INDEX 与 OCC ticker INDEX 时，选择值、请求、标签、来源链接及 daily/20/60 曲线均互不混用；无 OCC 记录不能用 Cboe 数值代替。 |
| AC-17 两份名单独立 | 市场名单增删、清空和并发冲突不改原个人 items/groups；原个人名单操作也不改市场名单或其 revision。 |

| AC-21 年度对照 | 验证普通日、休市日、闰日、早期历史不足、空数据；曲线只精确对齐，摘要回退最多7天，并显示实际比较日与覆盖数。 |
| AC-22 介绍页语言 | 正文、按钮、导航、图片说明与替代文本、弹窗说明及关闭按钮、html lang、页面标题和 meta description 随中英选择一致切换。 |

数据库行为由 `scripts/test-watchlists.mjs`、`scripts/test-market-settings.mjs` 和 `scripts/test-local-db.mjs` 验证；PCR 使用 backend/Cboe 的对应测试及原始数量复算；本机行情适配由 `scripts/test-moomoo.mjs` 验证。界面需补实际浏览器的名单、分组、日期切换和失败状态验收。部署成功前不把本轮能力标为线上已完成。

## 8. 已知差异与后续选择

- 当前规格以数据库 items/groups 契约及实际实现为基线；启动与本机凭证配置见 [中文 README](../README.zh-CN.md) 和 [moomoo 后端接入说明](MOOMOO_BACKEND.md)。
- 分组重命名目前仅由 API 整体更新支持；网页重命名入口是可选后续，不属于当前已完成的界面功能。
- OCC 若需要与 Cboe 完全一致的连续交易日缺口保证，需要另行改变活动记录窗口规则并做历史验证；当前不能宣称已经统一。
- moomoo 自选同步、专门行情展示、长期 OI 历史、盘中全市场 PCR、云桥及跨环境个人数据迁移，均需独立需求与授权，不由现有接口推定完成。
- 目前没有dealer Gamma/GEX、Gamma flip或可靠的做市商净头寸计算；不能由PCR或总OI直接推导。没有接入聊天模型或新闻流。

## 9. 源码结构与本地运行

| 位置 | 职责 |
| --- | --- |
| `web/` | 双语页面、图表、搜索、名单与历史比较交互；`web/archive/`为固定日期归档。 |
| `worker/` | OCC/Cboe数据接口、行情参考、个人/市场名单API及来源校验；构建时嵌入静态资源。 |
| `scripts/` | 构建、校验、本机Node预览、SQLite适配、moomoo只读适配与验证脚本。 |
| `drizzle/` | 可追踪的数据库结构迁移和元数据；已发布迁移不可随意修改或重新执行。 |
| `data/` | 构建使用的市场数据种子；个人数据库不在此目录。 |
| `docs/` | 本规格、数据口径和moomoo后端说明。 |
| `site/` | GitHub Pages 静态双语介绍页、`locale.js` 翻译与语言文档链接、英文演示媒体；不运行 PCR 后端。 |
| `AGENTS.md` | 开发维护规则及中英文文档同步要求。 |

本地运行依赖Node.js与Python 3：`node scripts/build.mjs`构建，`node scripts/preview.mjs`启动；默认绑定`http://127.0.0.1:8765/`。`PCR_DB_PATH`、`PCR_PREVIEW_PORT`、`PCR_PYTHON`可分别指定数据库、端口和Python。启动时应用受控迁移；关闭网页与停止后台是两件事。发行 ZIP 使用根目录的 `start.cmd`；既有本地部署也可使用外层的中文 CMD 启动器。两者都是本机便捷启动方式，不是云端服务。
