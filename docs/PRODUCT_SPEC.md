## 2. 用户故事

### US-01：维护自己的名单与分组（P1）

用户希望默认标的和后来加入的标的遵守相同规则，可以添加、删除、分类和恢复；网页支持创建自建分组、删除默认或自建分组。当前网页没有分组重命名入口，API 整体保存 groups 时可以修改名称。

独立验收：建立两个用户的名单；删除第一个用户的全部默认标的，新增 SNDK，创建中文分组，移动标的，删除分组，再重新打开页面。结果应来自数据库，第二个用户的名单不受影响。

### US-02：看懂当前读数与历史窗口（P1）

用户选择一个日期，查看单日、5 日、20 日和 60 日 PCR，以及来源与覆盖日期。没有该日完整报告时，页面要展示缺失或等待来源，而不是拿前一日数字冒充当天。

独立验收：用相同原始 Put/Call 数量分别复算三个周期；选择未发布日、历史日和一段有缺口的 Cboe 记录，检查空态、历史截止日及 OI 显示规则。

### US-03：多窗口保存不互相覆盖（P1）

用户在两个浏览器窗口编辑同一份名单时，较晚提交的旧版本不能悄悄覆盖另一窗口的新版本。

独立验收：两个窗口从相同 revision 保存不同名单；只有一个保存成功，另一个收到冲突，并显示服务器当前的名单和分组。

### US-04：在本机读取 moomoo 行情（P2）

用户在本机预览中读取报价、日 K、期权到期日及指定到期范围的期权链。连接或权限失败时显示实际失败状态，不能暗示已经取得实时行情。

独立验收：使用可控的 CLI 测试响应验证允许的查询、时间戳、超时和错误；确认交易或任意命令无法从网页调用。

### US-05：自由编辑市场 PCR 参考（P1）

用户希望上方市场 PCR 也能添加和删除。首次推荐 INDEX、TOTAL、ETP、EQUITY 四类 Cboe 与 SPY、QQQ、DIA 三只 OCC ETF，不意味着这些入口永久固定。合法 OCC 个股或 ETF 可以加入同一选择器；各项保留自己的来源与覆盖日期。

独立验收：删除全部七个推荐项并重开，名单仍为空；添加 SNDK 及一个与 Cboe 类别同文字的 OCC ticker，来源标识和曲线互不混用。更改市场名单不改变原个人名单或分组，反向操作也不联动。

### US-06：选择介绍页及文档语言（P1）

访客可以在 GitHub Pages 介绍页切换中文与英文，并进入对应语言的 README 和产品 Spec；回访时保留自己的语言偏好，英文演示图片与 GIF 保持原样。

GitHub 仓库默认展示英文 `README.md`；完整中文版保存为 `README.zh-CN.md`，`README.en.md` 保留为完整英文兼容副本。当前托管应用、管理员登录和介绍页首次无有效URL／已存偏好时默认英文；有效中文直达及既有中文偏好仍优先，可双向切换并保存。

独立验收：用中英文直达链接打开 `#preview`，切换语言、打开演示弹窗和文档链接，再次访问；检查语言、元信息、文档目标及手机布局。

### US-07：从独立异动页监测所选期权范围（P1）

用户从 PCR 与市场解读之间的顶部“期权异动”导航进入 /options-monitor.html，再选择自己的标的和数据来源：桌面模式选择到期日，查看有限行权价范围合约报价观察／真实逐笔；WebAPI 模式查看供应商标的汇总／异动事件，事件可按到期日筛选。界面必须说明扫描范围、来源时间及未知字段，不把局部 PCR、大额成交或 OI 变化解释成全市场净多空。

独立验收：切换标的与到期日，手动刷新并开启自动刷新；确认只在面板展开且页面可见时请求数据。模拟 moomoo 关闭、权限失败、部分缺失和重启，核查旧数据标记、数据库持久及原自选名单不变。

### US-08：刷新首页 OI 而不改写历史（P1）

用户希望灰色 OI 柱能读取已授权 Moomoo 的新汇总，而不一直停留在旧 Cboe 快照。首页默认选择最新 Moomoo，也可选已保存 Cboe；更新数据分别检查 OCC 成交量与 OI，并说明各自来源、检查时间和未知结算日。

独立验收：初次读取所选日归档而不联网，手动更新后检查双来源状态；模拟单边缺失和部分标的失败，不混旧侧数据、不重标旧时间。历史日仅有该日真实查询快照才显示灰柱；原种子及名单不变。

### US-09：本机定时报价复核（P2，未发布）

用户可在私有配置中指定一次观察时间、补跑截止时间、股票／期权及价差双腿，由已登录 Windows 用户的本机任务读取行情、保存结果并提醒回来复核。工具不交易、不自动调用 AI，也不把私人观察清单或结果上传。

独立验收：先执行无副作用 dry-run，再分别验证按时／补跑／过期、缺数据与授权失败、本机提醒及私有输出。未来计划任务已注册不等于已经执行或拿到未来行情。

### US-10：查看真实任务状态与历史复核（P2，本机未发布）

用户从“定时复核”查看 Windows 实际状态／下次运行、最近结果，以及按实际运行日期（纽约 ET）归档的报价。可刷新状态、筛选分页、查看及下载已发现的结果，同时了解本机归档次数和存储字节数。手动测试不等于定时任务已执行；无法查询调度器时明确未知。

独立验收：对比真实调度器与配置时间、区分手动／定时／失败／错过，测试 ET 跨日、分页和下载，并验证路径隔离、无清理或任务写入。云端显示仅本机支持，不展示伪造 Windows 状态。

## 3. 名单与分组需求

| 编号 | 要求 |
| --- | --- |
| WL-001 | 一份用户配置同时保存 `items` 和 `groups`，整体替换并共享一个 revision。 |
| WL-002 | `items` 最多 30 个去重后的 ticker，保持用户提供的顺序；重复 ticker 保留首项。 |
| WL-003 | ticker 去除首尾空白、转为大写，仅接受 ASCII 字母开头及字母、数字、点号，总长 1–10。 |
| WL-004 | 每项为 `{symbol, category}`；category 为存在于 groups 的 id，或 `null` 表示未分类。 |
| WL-005 | `groups` 最多 30 个，每项为 `{id, name}`。id 接受 `semi`、`etf`、`other` 或 `custom_` 加 1–64 位字母、数字、下划线、连字符。 |
| WL-006 | 分组名去除首尾空白后为 1–40 个字符，不包含控制字符；id 不重复，名称按去空白及大小写不敏感规则不重复。 |
| WL-007 | 网页支持创建自建分组、删除所有默认或自建分组；API 整体保存 groups 时可修改组名，当前网页没有重命名入口。`全部` 和 `未分类` 是派生视图，不是数据库分组。 |
| WL-008 | 删除分组时，同一次保存将其原有标的的 category 改为 null，保留这些股票；提交孤立 category 时拒绝保存。 |
| WL-009 | `items=[]`、`groups=[]` 都是有效的已保存状态。重新加载或新增标的时，不自动恢复已删除的默认项/默认组。 |
| WL-010 | 无记录时 GET 返回未初始化状态；只由前端首次迁移默认名单、旧浏览器自选及默认分组，并以 revision 0 提交一次。 |
| WL-011 | 移除自选只改变个人配置，不等于删除公共行情缓存。之后可以重新添加相同 ticker。 |
| WL-012 | 搜索建议是少量已整理公司名/中文名目录；也支持直接输入合法 ticker，不宣称覆盖全市场公司名称检索。 |
| WL-013 | 搜索框使用通用“输入股票或 ETF 代码”提示，不固定展示 SNDK。鼠标或方向键改变高亮；Enter 直接添加高亮候选，没有候选时使用当前输入代码。不能使用上次搜索的旧候选。 |
| WL-014 | 输入法组合中的 Enter 只用于确认输入；长按、重复 Enter、已关注代码与保存期间不能产生重复记录。无有效行情记录时不添加。 |

## 4. 配置数据与 API 契约

### 用户配置

数据库表为 `user_watchlists`，字段为 `owner_id`、`items_json`、`groups_json`、`revision`、`updated_at`。数据库迁移只定义结构，不写用户名单或默认分组；请求处理过程中不创建或修改表结构。

云端从平台提供的 `oai-authenticated-user-id` 决定 owner。请求体、查询参数或服务访问凭证不能选择个人数据的 owner。没有用户身份返回 401。本机预览由服务端注入 `local_user`，对应本机单用户配置，不代表实现了多用户登录。

### 读写

| 请求 | 行为 |
| --- | --- |
| `GET /api/watchlist-settings` | 返回 `{items, groups, revision, updatedAt, storage, initialized}`。没有记录时 items/groups 为 null、revision 为 0、initialized 为 false；不写数据库。 |
| `PUT /api/watchlist-settings` | 仅接受 `application/json` 的 `{items, groups, revision}`；完整请求体最多 8192 字节，仅接受同源请求。 |
| 首次 PUT | revision 必须为 0，通过原子插入建立 revision 1；若其他窗口已经初始化则返回 409。 |
| 后续 PUT | 只有数据库 revision 与请求一致时，才原子替换 items/groups 并将 revision 加 1。 |
| 冲突 | 返回 409 和服务器当前的完整配置；前端采用当前值，不能用旧编辑内容自动覆盖。 |
| 失败 | 输入错误、身份缺失、数据库不可用分别明确返回错误。未确认的保存不当作成功，不静默切换成浏览器名单。 |

示例请求：

```json
{
  "items": [
    {"symbol": "SPY", "category": null},
    {"symbol": "SNDK", "category": "custom_chips"}
  ],
  "groups": [{"id": "custom_chips", "name": "芯片观察"}],
  "revision": 3
}
```

`storage` 为 cloud 或 local，表示当前实际使用的数据库环境；不表示本地 SQLite 已同步到 D1。浏览器可保留语言等设备偏好，个人名单以数据库响应为准。

### 独立的市场 PCR 配置

市场 PCR 保存到独立表 `user_market_pcr`；原 `user_watchlists` 的个人名单和分组不因此迁移或互相联动。来源缓存可共用，但删除配置项不删除公共缓存，也不能因缓存仍存在就把该项重新加回名单。

| 请求或规则 | 契约 |
| --- | --- |
| `GET /api/market-pcr-settings` | 读取当前身份的市场名单。未初始化返回 items=null、revision=0、initialized=false；GET 不写记录。 |
| `PUT /api/market-pcr-settings` | 仅接受同源 JSON 请求，完整体最多 8192 字节；整体保存 `{items, revision}`，使用独立 revision 进行原子首次插入或比较后更新；冲突返回服务器当前名单，不自动覆盖。 |
| 市场项 | Cboe 为 `{type:"cboe", key:"index"|"total"|"etp"|"equity"}`；OCC 为 `{type:"symbol", symbol:"SNDK"}`。每项只接受相应的两个字段。 |
| 数量与去重 | 最多 40 个去重项并保持顺序；Cboe 类别与 OCC 大写 ticker 使用不同来源命名空间，不跨来源合并。 |
| 首次推荐与清空 | 仅未初始化时可以一次保存推荐七项；已保存 `items=[]` 是有效配置，重开、源失败或读取失败均不得恢复推荐项。 |
| 身份与隔离 | 延续平台可信身份、同源请求和数据库错误规则；市场名单与个人名单的内容、revision 和初始化状态分别处理。 |

例如 `{type:"cboe",key:"index"}` 与 `{type:"symbol",symbol:"INDEX"}` 是两个不同条目。前者读取 Cboe 指数分类，后者只有取得该 ticker 的 OCC 记录后才能展示其个股／ETF PCR；不能因名称相同而冒用另一来源的数据或标签。

## 5. PCR 与时间定义

### 计算口径

设某窗口内已验证的 Put 数量为 P、Call 数量为 C：

- 单日成交量 PCR：当日 P / C。
- 5 日成交量 PCR：对应窗口内 sum(P) / sum(C)，由已有每日成交张数派生。
- 20 日成交量 PCR：对应窗口内 sum(P) / sum(C)。
- 60 日成交量 PCR：对应窗口内 sum(P) / sum(C)。

5/20/60 日值不能用每日 PCR 的算术平均替代；Call 分母为零、历史不足或必要数据不可用时返回 null，页面显示缺失，不显示无穷大或虚构数值。

| 来源 | 范围与当前实现 |
| --- | --- |
| [OCC Volume Query](https://marketdata.theocc.com/volume-query) | 按单个 underlying 汇总来源合约侧数，单位为 contract sides。当前 5/20/60 窗口按已取得的活动记录行计算，coverage 会说明范围；缺失日期不补零。这与经过完整交易日校验的窗口不是同一个保证。 |
| [Cboe Daily Market Statistics](https://www.cboe.com/markets/us/options/market-statistics/daily) | 分开保留 INDEX、TOTAL、EXCHANGE TRADED PRODUCTS、EQUITY。直接来源单日使用官方发布的两位小数 PCR；历史重建 EQUITY 另标派生口径，详见 CBOE_SOURCE_SCOPE.md。5/20/60 使用有效 Put/Call 总量重新合计，窗口必须包含连续 5/20/60 个预期交易日及成交量，任何缺口使该窗口为 null。 |

Cboe INDEX 不是 SPY/QQQ/DIA 的 ETF PCR。各类别不可互换，个人分组也不改变来源口径。PCR 不表示做空人数、看空资金占比、股票空头持仓比例或未来涨跌概率。

新增 ticker 的历史与刷新状态独立保存；没有数据不能导致其他标的退回更早日期。选择图表显示长度不应改变同一日期的 5/20/60 窗口数值。

### 历史水平与往年同期

市场历史区提供“不比较”“历史分位”“往年同期”三个模式，属于查看偏好，不修改名单。标准模式保留单日、5 日、20 日、60 日四条成交量 PCR；年度对照一次只比较其中一个指标。

| 编号 | 可核查规则 |
| --- | --- |
| HC-001 | 先按所选截止日找到实际记录日。单日只与单日比，5 日只与5 日比，20 日只与20 日比，60 日只与60 日比；不跨标的、类别或来源合并样本。 |
| HC-002 | 各指标独立选实际记录日之前最近最多252个有限有效值；排除当前日及未来值。图表显示长度不改变分位计算样本。为此Cboe读取已保存完整历史，再在前端裁剪显示区间。 |
| HC-003 | 分位采用中位秩 `(低于当前值数量 + 0.5 × 等于当前值数量) / n`。同时展示历史中位数及实际样本数 `n / 252`；不足252明确标注，n=0或当前值缺失则分位为空。 |
| HC-004 | 年度曲线以所选日所属年份，与上年同月同日精确对齐，保留原始数据日期用于悬浮说明；非交易日、缺记录和无对应的2月29日留空，不补零、不插值。 |
| HC-005 | 年度摘要目标日为实际记录日减一年，2月29日目标调整为2月28日。摘要允许使用目标日前7天内最近一条记录，必须同时标目标日、实际比较日；无记录留空。此回退不用于年度曲线填充。 |
| HC-006 | 同期差值为当前PCR减去年PCR的倍数差，不称为百分比收益。展示可比较日期数及可用范围；样本不足不暗示完整多年历史。 |

历史分位反映相对活跃程度；99.6%不表示99.6%资金看空，也不表示预测成功率。年份对照只描述历史差异，不证明季节性因果或交易优势。

## 6. moomoo 本机后端与保密边界

官方 moomoo 文档将“读取自选分组”和“读取某组证券”分成两个接口，本文借鉴这种组与成员分开的组织方式；当前本产品的数据库自选独立维护，尚未接入 moomoo 自选名单同步。[读取分组](https://openapi.moomoo.com/moomoo-api-doc/en/quote/get-user-security-group.html)、[读取组内证券](https://openapi.moomoo.com/moomoo-api-doc/en/quote/get-user-security.html)。

桌面链路为：浏览器 → loopback Node 后端 → 固定 CLI → loopback moomoo 行情服务。可选 WebAPI 链路为：浏览器 → Node 后端 → 固定 moomoo HTTPS 行情接口。直接 API 不需要桌面进程，但需要独立 AccessToken；浏览器不持有凭证。云端 Worker 不包含桌面进程链，另行托管 WebAPI 需要部署与服务端 secret。

| 编号 | 要求与当前限制 |
| --- | --- |
| MM-001 | 供应商只读 GET 接口为 status、quotes、kline、expirations、option-chain、security-snapshots、option-trades；监测另提供固定 GET 缓存读取及受限 POST 刷新，规则在下方独立列出。完整快照接口保留独立能力与失败状态，不是监测必经路径。 |
| MM-002 | CLI allowlist 仅有 subscribe、get-basic-qot、get-kline、get-option-expiration-date、get-option-chain、get-security-snapshot、get-ticker；行情订阅只用于取得数据，不提供任意 CLI 命令入口。 |
| MM-003 | 桌面子进程使用参数数组及 shell:false，Host 仅接受 loopback。WebAPI 只访问固定 HTTPS 主机与只读路径；用户不能指定任意命令、标志、外部 Host 或凭证。 |
| MM-004 | 基础报价每次最多 20 个美股股票／期权代码；独立完整快照最多 100 个代码，逐笔单合约最多 200 笔。监测只扫最多 40 份合约，使用 get-basic-qot 分最多两批、每批 20 份取得成交量及 option_ex_data 内实际返回的 OI／IV 等字段，再取最多三个合约逐笔。日 K 最多 1000 根；期权链最多一个日历月到期范围，不等于全到期日 PCR 或全市场 OI。 |
| MM-005 | 供应商行情时间戳与 checkedAt 分别保留。连通、订阅成功或返回数据，不自动证明实时行情权限已核实。 |
| MM-006 | 桌面 AppKey 由后端环境或 Windows DPAPI 读取；本机 WebAPI 用独立 PKCE／DPAPI 按实际到期刷新，不接受手动 token、不写 .env。v0.2.7 云运行使用独立 quote:read OAuth：加密 Secret 引导、AES-GCM 私有密文保存、跨进程锁及实际有效期刷新；刷新授权失效仍需重新确认。DPAPI 不上传，凭证不进入网页、URL、源码、日志、Git 或发行包。 |
| MM-007 | 本机数据库、账户资料、持仓截图、私人行情响应和凭证文件不作为公开源码或公共种子数据。测试使用虚构身份与临时数据库。 |
| MM-008 | 不开放账户、持仓、订单、交易解锁、下单、改单、撤单等命令。 |

云端的 localhost 指向云端运行环境，不能据此访问用户电脑。个人电脑关闭、本机预览停止或 moomoo 服务停止时，这条本机行情链路不可用。云端公共 PCR 与云端 D1 名单依赖云端服务，与个人电脑是否开机分开判断。

受控云桥、用户主动上传脱敏快照或其他远程同步方案属于待选后续，当前未选型、未实现，也不纳入本轮已完成功能。

## 8. 已知差异与后续选择

- desktop 监测依赖桌面 Host；webapi 依赖独立 AccessToken、权限及网络，当前缺少 token 时明确未配置。两种路径均须实际查询，不能因文件或配置存在就声称已取得实时数据。

- 当前规格以数据库 items/groups 契约及实际实现为基线；启动与本机凭证配置见 [中文 README](../README.zh-CN.md) 和 [moomoo 后端接入说明](MOOMOO_BACKEND.md)。
- 分组重命名目前仅由 API 整体更新支持；网页重命名入口是可选后续，不属于当前已完成的界面功能。
- OCC 若需要与 Cboe 完全一致的连续交易日缺口保证，需要另行改变活动记录窗口规则并做历史验证；当前不能宣称已经统一。
- moomoo 自选同步、专门行情展示、盘中全市场 PCR 及跨环境个人数据迁移仍未完成。v0.2.7 已实现独立云端 OAuth 续期及持久任务状态；远程部署正在进行。只有实际取得的汇总 OI 才归档，不代表实时清算或已迁移本机数据库。
- v0.2.14增加供应商Gamma/GEX模型与Max Pain的独立读取契约，见下文；它们不是可靠观测的做市商净头寸，不能由PCR或总OI直接推导。没有接入聊天模型或新闻流。
